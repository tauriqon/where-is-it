## 1. 개선 배경 및 장애 원인 분석

### 1) 사용자가 겪은 장애 현상
- Tauriqon님의 제보:
  1. *"설정 의 보관위치관리 에서 저장소의 수정중 사진을 재 등록하기가 이상하다."*
  2. *"첫째 화면 터치가 안된다."* (사진 영역 터치 시 반응이 없음)
  3. *"둘째 x 를 누르면 사진이 지워지고 그다음 사진을 찍거나 입력하기 위해 터치해도 안된다."* (삭제 후 점선 박스 터치 시 반응 없음)
  4. *"그래서 이 수정용 바텀시트를 닫으면 사진 입력 메뉴가 떠있다."* (수정 모달을 닫고 나면 뒤에 사진 선택 메뉴가 열려 있음)

### 2) 근본 원인 분석 (Root Cause)
- **React 포털(Portal) 계층 구조 결함**:
  - 수납처/세부위치 수정 모달인 `BottomSheet`(`isEditLocationSheetOpen`)는 `createPortal`을 통해 `.app-wrapper` 루트에 직접 주입되고 `z-index: 1000`을 가집니다.
  - 반면 사진 촬영/앨범 선택 메뉴인 `ImagePickerBottomSheet`는 `createPortal`을 사용하지 않고 `SettingsTab` 컴포넌트 내부(`<main>` 내부)에 일반 DOM 자식으로 렌더링되고 있었습니다.
  - CSS Stacking Context 규칙상, `<main>` 내부의 요소는 아무리 `z-index`를 높여도 `.app-wrapper` 직계 자식으로 포털 주입된 모달보다 **물리적으로 항상 아래 계층**에 렌더링됩니다.
- **연쇄적 사용자 경험 오류**:
  - 사진을 터치하면 실제로는 사진 선택 바텀시트가 열렸으나, 수정 모달 **뒤쪽에 가려져** 사용자 눈에는 보이지 않았습니다 (화면 터치가 안 되는 것처럼 느껴짐).
  - 'X' 버튼을 누르면 사진이 지워지고 등록 박스를 다시 눌러도 여전히 수정 모달 뒤에 메뉴가 열려 있어 아무 반응이 없는 것처럼 보였습니다.
  - 결국 사용자가 수정 모달을 닫는 순간, 뒤에 가려져 있던 사진 입력 메뉴(`ImagePickerBottomSheet`)가 화면에 나타난 것입니다.

## 2. 세부 수정 사항

### 1) `ImagePickerBottomSheet`에 `createPortal` 및 최고 우선순위 z-index(11000) 적용 (`src/components/ImagePickerBottomSheet.tsx`)
- `react-dom`의 `createPortal`을 도입하여 `ImagePickerBottomSheet` 역시 `.app-wrapper` 최상위 계층에 포털로 직접 주입되도록 수정.
- `zIndex: 11000`을 부여하여 어떤 바텀시트나 모달(`z-index: 1000`)이 열려 있는 상태에서 사진 등록을 호출하더라도, **항상 모달보다 최상단 앞쪽**에 사진 촬영/앨범 선택창이 선명하게 나타나도록 보장.
- 사진 선택 완료 또는 취소 시 정상적으로 상위 모달로 부드럽게 복귀.

### 2) 사진 미리보기 영역 클릭 감지 범위 확장 (`src/components/SettingsTab.tsx`)
- 수납처 및 세부위치 사진 영역의 240px 컨테이너 `div` 전체에 `onClick={() => setImagePickerTarget('editStorage' | 'editSection')}`을 직접 바인딩하여, 이미지뿐만 아니라 여백 어디를 터치해도 즉각 사진 선택기가 열리도록 개선.
- 'X' 삭제 버튼의 `e.stopPropagation()`을 유지하여 사진 삭제 동작과 사진 변경 터치가 명확히 분리되도록 유지.

### 3) 사진 선택 시 클라이언트 선제 압축 파이프라인 연동 (`src/components/SettingsTab.tsx`)
- `handleImageSelected` 핸들러에 `compressImage`를 연동하여, 수납처/세부위치 사진 등록 시에도 250KB를 초과하는 고화질 원본은 즉각 1024px 모바일 최적 해상도로 압축 후 프리뷰 및 업로드되도록 안정화.
