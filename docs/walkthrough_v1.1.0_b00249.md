## 🔍 배경 및 원인 분석 (Problem & Root Cause)

### 1. 승인 과정 누락 원인
- 이전 빌드에서 가족 데이터 무손실 합치기(Merge) 기능 구현 과정 중, `handleConnectGroupCode`가 `submitJoinRequest(code, safeNickname)` 대신 `dbService.groups.join(code, safeNickname)`을 직접 호출하는 방식으로 변경되어 있었습니다.
- 그로 인해 참여 신청 버튼(`공유 보관소 참여 신청하기`)을 누르면 소유자에게 승인 요청이 전송되지 않고 즉시 멤버로 등록되어 보관소가 바로 공유되는 현상이 발생했습니다.

### 2. 복원 및 개선 내용
- **`SettingsTab.tsx` 가입 신청 절차 복원**:
  - `handleConnectGroupCode`에서 `dbService.groups.join` 직접 호출을 완전히 제거하고, `submitJoinRequest(code, safeNickname)`를 호출하여 정상적으로 `pending` 상태의 가입 신청이 생성되도록 복원하였습니다.
  - 신청 완료 시 신청자 화면에는 즉시 **[내가 신청한 보관소 (승인 대기 중)]** 카드가 노출되며 언제든 `[신청 취소]`할 수 있습니다.
  - 소유자 화면에는 **[보관소 가입 신청 (승인 대기)]** 목록에 신청자의 호칭(예: 엄마)과 대상 보관소명이 실시간으로 나타나며 `[승인]` 및 `[거절]` 버튼으로 승인 여부를 직접 결정할 수 있습니다.
- **호칭 입력 편의성 강화**:
  - 공유 코드 입력창 바로 아래에 `보관소 소유자에게 전달될 내 호칭` 입력창을 배치하여, 신청 전 원하는 호칭을 직관적으로 확인하고 입력할 수 있게 개선했습니다.
- **승인 처리 및 실시간 동기화 안전성 강화**:
  - `dbService.joinRequests.approve`에서 `group_members` 등록 시 `upsert`를 적용하여 재가입 시 발생할 수 있는 중복 키 충돌을 원천 차단했습니다.
  - 소유자가 승인을 누르면 신청자의 앱(3초 주기 백그라운드 폴링)이 승인을 즉시 감지하여, 가족 보관소로 활성 워크스페이스를 자동 전환하고 환영 알림을 제공합니다.
