## 1. 문제 분석 및 원인 규명
- **현상**:
  - 사진(USB 젠더) 촬영/등록 시 물건 이름 입력란에 단일 물건 이름 대신 `{ name: USB 젠더,  tags: [전자부품, ` 와 같이 미완성된 JSON 문자열이 그대로 노출됨.
- **원인**:
  1. **토큰 수 부족에 따른 응답 절단**:
     - 기존 `aiVision.ts`에서 설정된 `maxOutputTokens`가 `60`으로 너무 작았습니다.
     - 한국어 형태소 토큰화 특성상 JSON 키(`name`, `tags`)와 한국어 이름 및 3개 태그를 출력하기에 60토큰은 부족하여, 태그 출력 도중 응답이 강제 절단(`FINISH_REASON: MAX_TOKENS`)되었습니다.
  2. **JSON 파싱 실패 시 폴백 처리 결함**:
     - 응답이 도중에 끊겨 닫는 중괄호(`}`)가 없자 `JSON.parse`가 실패했습니다.
     - 기존 폴백 로직이 파싱 실패 시 원본 문자열의 특수기호만 제거하고 그대로 `name` 필드로 반환하여, 잘려진 JSON 구조체가 사용자 인풋에 그대로 입력되었습니다.

---

## 2. 해결 방안 및 세부 변경 사항 (`src/services/aiVision.ts`)

### 1) 토큰 제한 확장 및 구조화 JSON 출력 보장
- `maxOutputTokens`를 `60`에서 `300`으로 대폭 확장하여 응답이 도중에 끊길 위험을 원천 차단했습니다.
- `generationConfig`에 `responseMimeType: 'application/json'`을 적용하여 Gemini가 항시 유효하고 완전한 순수 JSON 객체만을 출력하도록 강제했습니다.

### 2) 3중 정밀 파서 및 정규식 폴백 구축
1. **1차 (표준 파싱)**: 마크다운 코드블록 제거 후 `JSON.parse` 수행.
2. **2차 (블록 슬라이싱)**: 최외곽 중괄호(`{ ... }`) 위치 기반 파싱 시도.
3. **3차 (정규식 비정형 추출)**:
   - 만약 네트워크 단절 등으로 JSON이 불완전하게 잘리더라도, 정규식(`"name": "..."`, `"tags": [...]`)을 통해 이름과 태그를 각각 분리 추출.
   - 이름이나 태그가 잘려있어도 순수 물건 이름(예: `USB 젠더`)만 안전하게 추출하여 이름 인풋에 반영.
4. **4차 (JSON 잔여물 철저 소거)**:
   - 추출된 이름에서 중괄호(`{`, `}`), 대괄호(`[`, `]`), 콜론, `name:`, `tags:` 등의 JSON 구문 잔여물이 남아있지 않도록 정제.

- **테스트 시나리오 검증**:
  - 절단된 JSON 응답(`{ name: USB 젠더,  tags: [전자부품, `) ➔ `{ name: 'USB 젠더', tags: ['전자부품'] }`으로 정상 분리 추출 확인.
  - 완전한 JSON 응답 ➔ 정상 파싱 확인.
  - 마크다운 코드블록 포함 응답 ➔ 정상 파싱 확인.
  - 비정형 텍스트 응답 ➔ 순수 텍스트만 안전하게 이름으로 채택.
