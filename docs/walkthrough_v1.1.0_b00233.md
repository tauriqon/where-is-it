## 🔍 상세 개선 내용

### 1. 설정 내 폰트 규격 및 타이포그래피 정렬
- **문제점**: 이전 빌드에서 스크롤을 방지하기 위해 복구 페이지의 글자 크기를 축소(`12px`, `9.5px`, `13.5px` 등)하면서, 설정의 다른 하위 페이지(내 호칭 변경, 유통기한 설정 등) 대비 글자가 눈에 띄게 작아 보이는 불균형이 발생했습니다.
- **해결 내역**:
  - 서브페이지 헤더 제목: `20px` (표준 h2-title 규격 복원)
  - 서브페이지 설명: `13.5px` (표준 body-desc 규격 복원)
  - 카드 제목: `16px` (표준 카드 헤딩 규격)
  - 카드 설명 문구: `13.5px` (가독성 높은 본문 규격)
  - 복구 코드 표시: `19px` (가독성 높은 monospace)
  - 입력창 및 버튼: `14.5px`, 높이 `44px` (표준 토스 모바일 규격)
  - **공간 최적화 유지**: 여백과 패딩을 조율하여 타이포그래피는 다른 항목과 완벽히 동일한 크기를 유지하면서도 모바일 뷰포트에서 스크롤 없이 한눈에 들어오는 레이아웃을 완성했습니다.
  - **설정 메인 메뉴 강화**: 메인 설정 리스트의 '내 호칭 / 이름 변경' 항목 하단에 `(현재: Ed.Kim)`과 같이 현재 설정된 호칭이 바로 노출되도록 보강했습니다.

### 2. 보관소 복구 시 기존 호칭('Ed.Kim') 자동 복원 및 상속
- **원인 분석**:
  - Tauriqon님께서 앱을 초기화하면 새로운 익명 세션(`user_id`)이 생성됩니다.
  - 기존 `restoreByCode` 로직에서는 `group_members` 테이블에서 '신규 익명 사용자 ID'에 바인딩된 이전 닉네임을 조회하려 했기 때문에, 신규 사용자에게는 이전 기록이 없어 기본값인 `'소유자'`로 저장되었습니다.
  - 실제 Tauriqon님의 호칭인 `'Ed.Kim'`은 복원 대상 보관소(`wii-fz3bkx`)의 기존 멤버 이력에 안전하게 보존되어 있었습니다.
- **해결 내역**:
  - `restoreByCode` 개선: 복구 코드로 보관소를 복원할 때, 복원 대상 보관소의 기존 소유자/멤버 이력에서 커스텀 호칭을 우선적으로 탐색하여 신규 세션에 자동으로 이어받도록(`userName = vaultOwnerMembers[0].user_name`) 개선했습니다.
  - `refreshActiveGroupMembers` 자동 동기화 탑재: 현재 세션의 호칭이 기본값 `'소유자'`로 되어 있더라도, 해당 보관소에 기저장된 커스텀 호칭(`'Ed.Kim'`)이 존재하면 즉각 메모리와 Supabase 데이터베이스에 자동 상속·동기화되도록 안전장치를 구축했습니다.
  - **결과**: 앱을 켜거나 새로고침하면 Tauriqon님의 호칭이 `'Ed.Kim'`으로 즉각 정상 복구됩니다.
