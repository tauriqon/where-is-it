## 🔍 문제 원인 분석 (Root Cause Analysis)

### 1. 수정 중 실시간 임시저장(Draft) 및 자동 복원 메커니즘의 부작용
- 이전 `v00222` 빌드에서 작업 중단 대비용으로 키 입력 시마다 `localStorage.setItem('wii_edit_item_draft_${itemId}', ...)`를 수행하고, 시트가 열릴 때마다 해당 키를 감지하여 자동으로 `setIsEditing(true)`를 호출하며 폼 값을 덮어쓰는 로직이 적용되어 있었습니다.
- 이로 인해 사용자가 수정 중 `[수정 완료]`를 누르지 않고 `✕`나 배경 터치로 시트를 닫았을 때:
  - 실제 DB에는 수정 사항이 반영되지 않았으나 로컬스토리지에 미저장 드래프트가 남아있었습니다.
  - 이후 동일 물건을 다시 열면 로컬스토리지의 드래프트를 읽어와 `setIsEditing(true)`를 강제 호출함으로써, 마치 **"수정완료를 선택하지 않았는데 정보가 수정된 것처럼"** 보이고 **"물건 클릭 시 바로 수정중 화면으로 들어가는"** 치명적인 결함이 발생했습니다.
- 상단 `... X`로 앱을 빠져나갔다가 재진입한 경우에도 로컬스토리지에 드래프트가 영구 잔존하여 동일한 문제가 반복되었습니다.

## 🛠️ 주요 변경 및 개선 사항

### 1. 물건 수정 임시저장 영구 캐시 메커니즘 완전 폐기
- 물건 정보 수정 작업은 사용자가 `[수정 완료]` 버튼을 누르기 전까지는 React 컴포넌트 내부 State로만 격리 관리되도록 전면 개선하였습니다.
- 키 입력 시마다 로컬스토리지에 저장하던 `useEffect` 및 시트 오픈 시 `setIsEditing(true)`를 강제하던 자동 복원 `useEffect`를 `ItemDetailBottomSheet.tsx`, `ExploreTab.tsx`, `SearchTab.tsx`에서 완전히 제거하였습니다.

### 2. 미완료 수정 중 이탈 시 안전 확인 팝업 통일
- 물건 수정 화면에서 이탈하는 4가지 경로 전체에 안전 가드를 일관되게 적용하였습니다:
  1. **바텀시트 상단 `✕` 닫기 버튼 터치**
  2. **바텀시트 외부 배경(Backdrop) 터치**
  3. **헤더 좌측 뒤로가기(`<`) 버튼 터치**
  4. **하단 `[취소]` 버튼 및 토스 네이티브 뒤로가기 이벤트**
- 수정 중 변경사항(`hasUnsavedChanges`)이 존재하는 경우:
  - `"수정 중인 내용이 있습니다. 변경사항을 저장하지 않고 나가시겠습니까?"` 컨펌 팝업 표출
  - **[취소]** 선택 시: 현재 수정 모드 유지
  - **[확인]** 선택 시: 편집 중이던 임시 입력값을 원래 물건 정보(`currentItem`)로 깔끔하게 롤백(`handleCancelEdit()`)하고 안전하게 시트 닫기 또는 상세 뷰로 복귀

### 3. 앱 기동 시 잔존 드래프트 일괄 소거 (`App.tsx`)
- 기존 사용자 기기에 이미 저장되어 남아있던 불필요한 `wii_edit_item_draft_*` 로컬스토리지 키들을 앱 최초 마운트 시 일괄 탐색하여 완전히 삭제하도록 안전 클린업 로직을 추가하였습니다.
