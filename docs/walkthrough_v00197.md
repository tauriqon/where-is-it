# 🔍 WhereIsIt 비동기 이미지 로딩 시 WebKit Flexbox 찌그러짐 원천 차단 및 고정 픽셀 계산 엔진 탑재 (v00197)

본 문서는 WhereIsIt 미니앱에서 **캐시되지 않은 신규 등록 물건의 수납처/세부위치 사진을 처음 클릭하여 확대할 때 사진이 모달 중앙에 약 49px×66px 크기의 아주 작은 썸네일로 찌그러져 표시되던 현상의 근본 원인을 규명하고, 고정 픽셀 치수 계산 엔진을 도입하여 완전히 해결한 내역**을 정리한 워크스루(Walkthrough)입니다.

---

## 1. [v00197] 심층 원인 분석: 왜 기존 등록 물건은 정상이고, 신규 등록 물건은 작게 보였을까?

### 1.1. 브라우저 캐시 유무와 WebKit(Safari) 렌더링 사이클의 차이
1. **기존 물건("십자드라이버" - "책장1")이 정상적으로 보인 이유**:
   - 사용자가 이전 버전에서 이미지를 열어보았거나 브라우저 메모리/디스크 캐시에 해당 이미지의 바이트와 메타데이터(`naturalWidth: 768, naturalHeight: 1024`)가 이미 적재되어 있었습니다.
   - 따라서 모달이 열리는 시점에 이미지가 동기적으로(Synchronously) 준비되어 있어 Safari가 정상적인 치수로 플렉스 레이아웃을 계산할 수 있었습니다.
2. **새로 등록한 물건("가위" - "싱크대")이 작게(49px×66px) 보인 이유**:
   - 방금 등록된 신규 이미지는 브라우저 캐시에 존재하지 않으므로, 모달이 열리는 첫 프레임 시점에 `naturalWidth`가 `0`인 상태입니다.
   - `width: auto`, `height: auto`로 지정된 플렉스 자식 이미지는 다운로드가 완료되기 전까지 Safari가 기본 대체 요소 플레이스홀더 크기(약 49px×66px)로 플렉스 박스를 초기 고정합니다.
   - **WebKit 엔진의 심각한 결함**: 이후 백그라운드에서 이미지 다운로드가 끝나더라도, 플렉스 박스 조상 컨테이너의 레이아웃 리플로우(Reflow)를 다시 수행하지 않아, 뒤늦게 로드된 고화질 이미지가 초기 계산된 49px×66px 박스 안에 강제로 갇혀 찌그러지게 됩니다.

## 2. 주요 해결 및 개선 내역

### 2.1. JavaScript 기반 실시간 픽셀 치수 계산 엔진 구축 (`src/App.tsx`)
- CSS의 `auto` 치수나 브라우저의 플렉스 자동 축소 로직에 의존하지 않고, **JavaScript 메모리 상에서 이미지를 사전 디코딩(`new Image()`)하여 실제 종횡비(`naturalWidth / naturalHeight`)와 현재 디바이스 뷰포트 크기를 기반으로 최적의 픽셀 값(`displayWidth`, `displayHeight`)을 직접 계산**합니다.
- 계산된 치수는 인라인 스타일 `width: 359px; height: 478px;` 형태로 요소에 직접 고정 주입되므로, WebKit이 치수를 자의적으로 축소하거나 찌그러뜨릴 여지를 100% 원천 차단했습니다.

### 2.2. 로딩 스피너 및 듀얼 디코딩 안전망 연동
- 네트워크 상태에 따라 신규 이미지가 다운로드되는 0.1~0.3초 동안 부드러운 스피너(`spin` 애니메이션)와 "사진 불러오는 중..." 안내를 띄워 레이아웃 깜빡임을 방지했습니다.
- 백그라운드 `new Image()` 프리로더와 DOM `<img>`의 `onLoad` 및 `ref.complete` 3중 안전망을 연동하여, 캐시 여부와 무관하게 100% 안정적으로 고화질 전체 화면 크기로 펼쳐지도록 보장했습니다.

### 2.3. 전역 `spin` 애니메이션 키프레임 보강 (`src/index.css`)
- `src/index.css`에 `@keyframes spin`을 전역 선언하여 앱 전반의 로딩 인디케이터 신뢰성을 확보했습니다.
