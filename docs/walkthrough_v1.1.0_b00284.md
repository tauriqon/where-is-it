## 1. 개선 배경 및 사용자 요청 사항

### 1) 사용자가 겪은 현상 및 요청 (Tauriqon님)
1. *"안드로이드폰에서는 여전히 종료의 문제가 있는데?? 심지어는 x버튼을 눌러도 인식이 안되는 것 같은 현상도 있다. 여러번 누르거나, 좀 길게 누르면 되는 경우가 있다."*
2. *"설정 안의 [앱 종료하기]를 눌러도 같은 현상이다."*
3. *"위의 설명대로라면 현재 상황에서 최적화를 하고, 설정안의 [앱 종료하기]는 없애자."*
4. *"그리고 초기버전에 있던 [뒤로가기] 를 다시 배치해서 확인해 보자."*

### 2) 기술적 배경 분석
- **설정 내 [앱 종료하기] 버튼의 중복 및 한계**:
  - 설정 탭의 [앱 종료하기] 버튼은 내부적으로 `closeView()`를 호출하므로, 네이티브 X 버튼이나 하드웨어 뒤로가기와 동일한 토스 웹뷰 종료 파이프라인을 거칩니다.
  - 별도의 설정 버튼으로 노출되어도 근본적인 웹뷰 종료 라이프사이클을 개선하지 못하고 UI만 복잡하게 만들므로 사용자 지침에 따라 완전히 제거하였습니다.
- **네이티브 네비게이션 뒤로가기 버튼(`withBackButton`) 히스토리**:
  - 초기 버전(`b00073` ~ `b00224`)에서는 네이티브 상단 네비게이션 바에 `[ < ]` 뒤로가기 버튼이 항상 노출되어 있었습니다.
  - `v1.0.0-b00225` 당시 토스 1차 심사 피드백(*"내비게이션 바의 뒤로가기 버튼과 미니앱 자체 헤더 및 뒤로가기 버튼이 함께 노출돼요. 중복된 버튼을 제거해 주세요."*)에 대응하여 `withBackButton: false`로 숨김 처리한 바 있습니다.
  - 그러나 안드로이드 기기에서는 물리/제스처 뒤로가기만 사용할 경우 포커스 상태나 웹뷰 오버헤드로 인해 즉각적인 반응을 체감하기 어려운 상황이 발생하여, 이번 빌드에서 초기버전의 네이티브 `[ < ]` 버튼을 다시 배치하여 반응성과 사용성을 테스트하기로 결정하였습니다.
- **안드로이드 터치 지연/무반응 원인 (IME 포커스 간섭)**:
  - 안드로이드 크로미움 웹뷰에서는 텍스트 입력 필드(`input`, `textarea`)가 포커스되어 있거나 가상 키보드가 완전히 닫히지 않은 상태에서 상단 헤더 영역이나 버튼을 누르면, **첫 번째 터치 이벤트가 "키보드 닫기 및 포커스 아웃(blur)" 이벤트로 소비**되어 실제 클릭이 무시되거나 두 번 눌러야 작동하는 현상이 자주 일어납니다.

## 2. 세부 작업 내역

### 1) 토스 네이티브 뒤로가기 버튼 복원 (`granite.config.ts`, `apps-in-toss.config.ts`)
- `navigationBar` 설정에서 `withBackButton: true`로 원복.
- 토스 상단 앱 헤더 좌측에 네이티브 `[ < ]` 뒤로가기 화살표가 노출되며, 터치 시 토스 브릿지 `backEvent`가 호출됩니다.

### 2) 설정 탭 내 불필요한 [앱 종료하기] 버튼 제거 (`src/components/SettingsTab.tsx`, `src/App.tsx`)
- `src/components/SettingsTab.tsx` 하단의 `[🚪 앱 종료하기]` 버튼 UI 컨테이너(24줄)를 완전히 삭제.
- 사용되지 않는 `LogOut` 아이콘 import 및 `onTriggerExit` Props 인터페이스와 바인딩 정리.

### 3) 안드로이드 뒤로가기 및 이벤트 최적화 (`src/App.tsx`)
- **선제적 포커스 블러(`activeElement.blur()`)**:
  - `handleBackAction` 진입 즉시 `document.activeElement.blur()`를 실행하여 활성화된 입력 포커스와 키보드를 강제 해제, 이벤트가 키보드에 먹히지 않고 앱 제어로 즉각 전달되도록 조치.
- **`handleBackActionRef` 패턴 적용을 통한 리스너 불필요한 재등록 방지**:
  - 기존에는 `[activeTab, settingsSubPage]` 변경 시마다 `backEvent` 리스너를 해제하고 다시 등록하는 불필요한 오버헤드가 있었습니다.
  - `handleBackActionRef`를 도입하여 마운트 시 단 1회만 네이티브 리스너를 안정적으로 등록하고, 항상 최신 상태의 탭 및 모달 구조를 참조하도록 개선.
- **종료 확인 모달 열림 상태에서의 뒤로가기 예외 처리**:
  - 앱 종료 확인 팝업(`isExitModalOpen`)이 떠 있는 상태에서 뒤로가기 버튼을 누르면 팝업이 부드럽게 닫히도록 LIFO 스택 최우선 분기 추가.

### 4) 버전 및 빌드 넘버 업데이트
- `src/version.ts`: `APP_BUILD_NUMBER = 'b00284'`
- `.env`: `VITE_APP_VERSION=v1.1.0-b00284`
