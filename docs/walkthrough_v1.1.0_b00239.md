## 🔍 에러 원인 정밀 분석 (Root Cause)

### 1. 현상
- 앱 실행 시 간헐적으로 다음 팝업이 노출됨:
  > **"Supabase 설정이 필요해요"**<br>
  > Error Details: `사용자 세션을 불러오는 중 응답이 지연되었습니다.`<br>
  > 💡 해결 방법 (익명 로그인 켜기) 안내 화면 표시

### 2. 기술적 근본 원인
1. **Supabase 익명 로그인은 이미 정상 작동 중**:
   - Tauriqon님의 Supabase 프로젝트는 이미 Anonymous Sign-in이 활성화되어 있으며, 실제 호출 시 500ms 만에 정상 응답합니다.
2. **블로킹 원격 서버 호출(`getUser()`)과 짧은 10초 타임아웃**:
   - 기존 `dbService.auth.getCurrentUser()`는 앱 실행 시마다 Supabase 원격 서버로 HTTP 네트워크 요청(`supabase.auth.getUser()`)을 보냈습니다.
   - 모바일 네트워크(LTE/5G) 지연이나 기기 백그라운드 복귀 찰나에 응답 시간이 10초를 초과하면, `withTimeout`이 작동하여 타임아웃 예외를 발생시켰습니다.
3. **오해를 부르는 포괄적 에러 화면**:
   - `App.tsx`에서 `authError` 발생 시, 단순 네트워크 일시 지연임에도 불구하고 무조건 "익명 로그인을 켜세요"라는 설정 안내 화면을 띄워 사용자에게 큰 혼란을 주었습니다.

## 🛠️ 해결 및 개선 상세

### 1. 0ms 로컬 세션 캐시 즉시 복원 체계 구축 (`dbService.auth.getCurrentUser`)
- **위치**: `src/services/db.ts`
- **구현 내용**:
  - 앱 시작 시 원격 네트워크 요청을 기다리지 않고, Supabase SDK가 기기 내부(`localStorage`)에 보관해 둔 세션 토큰(`supabase.auth.getSession()`)을 **0.001초(0ms) 만에 즉시 확인**하여 세션을 복원합니다.
  - 기존 사용자는 네트워크 상태와 무관하게 **대기 시간 0초 만에 즉시 앱 메인 화면으로 진입**합니다.
  - 토큰 갱신 및 유효성 검증은 백그라운드에서 비동기로 수행되어 앱 시작 속도를 일체 저해하지 않습니다.

### 2. 타임아웃 시간 연장(20초) 및 자동 폴백 방어 로직
- **위치**: `src/contexts/AuthContext.tsx`
- **구현 내용**:
  - 모바일 통신 음영 지역 등을 고려하여 타임아웃을 기존 10초에서 **20초**로 대폭 여유 있게 확대.
  - `getCurrentUser`에서 예외가 발생하더라도 바로 앱을 중단하지 않고, `signInAnonymously()` 자동 재시도 폴백을 거쳐 최대한 자연스럽게 세션을 확보합니다.

### 3. 일시적 네트워크 지연 전용 안내 UI 분리
- **위치**: `src/App.tsx`
- **구현 내용**:
  - `authError` 발생 시 에러 유형을 지능적으로 분류:
    - **통신/타임아웃 지연**: `📡 네트워크 연결이 지연되고 있어요` 문구와 함께 "잠시 후 [다시 시도하기]를 누르시면 저장된 세션으로 즉시 재접속됩니다"라는 명확한 안내 제공.
    - **실제 설정 누락(Provider Disabled)**: 실제 익명 로그인이 꺼져 있을 때만 `🛠️ Supabase 설정이 필요해요` 안내창 표시.
