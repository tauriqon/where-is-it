# 📐 WhereIsIt 토스 상단 ✕ 강제 종료 대응 영구 드래프트(localStorage) 및 자동 복원 시스템 구축 (v00220)

본 문서는 WhereIsIt 미니앱에서 **토스 앱 상단 네이티브 헤더의 [··· ✕] 중 ✕(닫기) 버튼 터치 시 네이티브 쉘의 강제 종료 정책으로 인해 웹뷰 알럿이 차단되는 구조적 한계를 규명하고, 사용자가 작성 중이던 모든 데이터가 단 1글자도 유실되지 않도록 `localStorage` 기반 영구 드래프트 자동 저장 및 자동 복원 시스템을 구축한 내역**을 정리한 워크스루(Walkthrough)입니다.

---

## 1. 문제 분석 및 토스 네이티브 구조의 한계

1. **사용자 제보 현상 (Tauriqon님)**:
   - "확인창 안뜬다." (토스 상단 [··· ✕] 중 ✕ 버튼을 눌러 종료할 때 확인창이 뜨지 않고 바로 종료됨)

2. **기술적 원인 규명 (토스 플랫폼 보안 및 아키텍처 원칙)**:
   - **네이티브 호스트 쉘의 강제 비상구 (Emergency Exit)**:
     - 토스 앱 상단의 `[··· ✕]` 중 `✕` 버튼은 미니앱 웹뷰 내부의 요소가 아니라 **토스 앱 네이티브 컨테이너가 띄워놓은 시스템 닫기 버튼**입니다.
     - 토스 플랫폼 심사 및 운영 정책에 따라, 악성 웹뷰나 무한 루프, 스크립트 프리징 등으로부터 사용자를 보호하기 위해 **상단 ✕ 버튼은 웹뷰(JavaScript)의 확인이나 이탈 방해를 일절 거치지 않고 네이티브 레벨에서 액티비티를 즉시 강제 종료(Kill / Finish)**하도록 설계되어 있습니다.
     - 따라서 `window.confirm`이나 자바스크립트 모달로 상단 `✕` 버튼의 종료를 멈추는 것은 토스 네이티브 OS 차원에서 원천적으로 차단됩니다. (기기 뒤로가기 버튼은 `backEvent`를 통해 확인창 제어 가능)

3. **핵심 해결 방향**:
   - 상단 `✕` 버튼으로 앱이 불시에 종료되더라도, **사용자가 작성 중이던 데이터(이름, 사진, 수량, 메모, 위치, 태그 등)가 100% 안전하게 살아남아 재실행 시 완벽히 복원**되도록 구조를 전환해야 합니다.

## 2. 주요 해결 및 변경 내역

### 2.1. 세션 스토리지(`sessionStorage`) → 로컬 스토리지(`localStorage`) 영구 드래프트 전환 (`src/components/AddTab.tsx`)
- 기존 `sessionStorage`는 앱(웹뷰)이 종료되면 메모리에서 즉시 소멸하는 치명적인 단점이 있었습니다.
- 이를 `localStorage`로 전환하여 **토스 상단 ✕ 버튼으로 앱이 즉시 꺼지더라도 기기 로컬 저장소에 작성 데이터가 영구 보존**되도록 개선했습니다.

### 2.2. 등록 탭 진입 시 자동 복원 및 알림 배너 연동
- 사용자가 앱을 다시 실행(홈 화면으로 시작)한 후, 언제든 **'등록' 탭**을 터치하면:
  - 이전에 작성 중이던 이름, 설명, 수량, 태그, 유통기한, 선택했던 공간/수납처/세부위치 등이 **자동으로 100% 복원**됩니다.
  - 폼 상단에 안내 배너 표시:
    ```
    [📝 이전에 작성 중이던 내용이 복원되었습니다.] [새로 쓰기]
    ```
  - **[새로 쓰기] 버튼**: 클릭 시 확인 후 드래프트를 깨끗하게 비우고 새 양식으로 리셋.
  - **[저장] 버튼**: 이어서 작성 완료 후 저장 시 드래프트 자동 소거.
  - **[취소] 버튼**: 취소 확인 시 드래프트 영구 소거.

### 2.3. 위치 추가 연동 지원 (`src/components/SettingsTab.tsx`)
- 설정 탭의 [+ 새 공간/수납처/세부위치 추가]를 통해 새로운 보관 구조를 생성하고 돌아올 때도 `localStorage`와 완벽히 동기화되도록 연동 로직을 일치시켰습니다.
